# GPT-6 Astra 프런트 개발 기준

GPT-6 Astra를 사용하는 프런트 개발·검토 작업의 기준이다. 실제 사용자 동작과 유지보수 비용으로 설계를 판단한다. 모델 이름이 바뀌었다는 이유만으로 제품의 의존성이나 API를 교체하지 않는다.

## 작업 순서

1. 관련 구현과 [아키텍처](architecture.md)를 읽고 사용자가 원하는 결과를 한 문장으로 정한다.
2. 현재 호출부와 실패 경로를 확인하고 수정 전후를 구분할 입력·화면 결과를 정한다.
3. 가장 작은 일관된 변경을 구현한다. 계약이 달라지면 직접 연결된 호출부와 관련 검증을 맞춘다.
4. [테스트 가이드](testing.md)에서 변경 범위에 맞는 검사를 실행하고 diff를 검토한다.
5. 실제 동작·명령·설계 이유가 달라진 문서만 갱신한다. 결과와 검증하지 못한 범위를 구분해 보고한다.

파일 수·테스트 수·코드 길이를 성과 목표로 삼지 않는다. 독립적인 조사가 필요한 경우에만 병렬 검토를 활용하고, 결과는 현재 코드와 실행 근거에 대조한다.

## 단순화 판단

| 대상 | 기본 판단 | 보존할 동작 |
|---|---|---|
| 상태와 ref | 다른 값에서 계산할 수 있으면 중복 저장하지 않음 | 현재 선택·로딩·실패 구분 |
| 훅과 공용 모듈 | 실제로 같은 책임·입력·수명을 공유할 때 추출 | 호출부별 필요한 도메인 판단 |
| 캐시·진행 중 요청 | 기존 공유 요청 모듈부터 확인 | 취소, 늦은 응답 차단, 만료와 로그아웃 정리 |
| 생성 복구 | 서버가 요청을 식별할 수 있으면 그 계약으로 단순화 | 응답 유실 후 중복 생성 방지 |
| 리포트 프로토콜 | 생산자·소비자의 범위와 한도를 함께 맞춤 | origin·문서 identity·메시지 검증 |
| 테스트 | 실제 함수 또는 사용자 동작의 결과를 검증 | 접근성 이름·오류·재시도·취소 회귀 |
| UI 추상화 | 한 화면의 단순 동작은 해당 화면에 둠 | 반복 사용되는 의미·입력·포커스 일관성 |

새 전역 상태 라이브러리, 범용 작업 엔진, 추가 캐시 계층은 실제 문제가 있을 때만 검토한다. 현재 사용처가 없는 확장점과 가상의 미래 요구를 위해 코드를 늘리지 않는다.

기존 복구나 검증을 없애기 전에 어떤 실패를 막는지 확인한다. 프로젝트 생성 API의 요청 식별자 보장을 페이지 생성·분석 POST에도 있다고 가정하지 않는다. 서버 계약이 필요한 변경은 그 의존성을 명확히 기록하고 작업 범위에 맞춰 처리한다.

## 데이터와 UI의 기준

- 로딩, 자료 없음, 실패와 실제 0점은 서로 다른 상태다.
- 현재 URL·요청·문서에 속한 결과만 화면을 갱신해야 한다.
- 요청 하나의 실패가 관계없는 자료를 지우지 않아야 한다.
- 리포트 연결 성공과 모든 이슈의 위치 확인 완료를 구분한다.
- 상태는 색상뿐 아니라 레이블·수치·읽을 수 있는 안내로 전달한다.

이 기준은 기대 동작이다. [확인된 프런트 오류](architecture.md)는 별도로 남기고, 문서에서 기대 동작을 적었다는 이유로 해결된 것으로 처리하지 않는다.

## 검증 비용

문서만 바꾸면 로컬 링크, 파일 경로, 명령·환경 변수의 구현 일치를 확인한다. 제품 빌드와 전체 브라우저 검사를 일괄 재실행할 필요는 없다.

단순 로직은 해당 단위 테스트, 화면 변경은 빌드와 관련 브라우저 회귀부터 실행한다. 공용 데이터·라우팅·여러 화면이 영향을 받으면 `npm test`로 넓힌다. CSS 수치 검사는 해당 시각·레이아웃 검증에 두고 일반 기능 검사를 소스 문자열이나 DOM 깊이에 묶지 않는다.

브라우저 회귀는 `npm run test:list`에서 확인한 뒤 `npm run test:run -- --test <파일>`로 선택한다. 관련 테스트가 여러 개면 `--test`를 반복해 같은 서버에서 실행한다. 전체 CI의 검사 범위는 축소하지 않는다. 실행별 `results.json`과 로그를 근거로 결과를 판단하고, 실패를 고친 뒤 필요한 항목을 명시적으로 재실행한다.

실패한 검사를 삭제하거나 기대값을 낮춰 완료로 만들지 않는다. 이전 통과 결과를 이번 실행처럼 보고하지 않는다. 환경 문제로 실행하지 못한 검사는 제품 결함과 구분해 기록한다.
