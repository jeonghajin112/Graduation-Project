# 디자인 시스템

현재 UI를 유지·확장할 때의 기준이다. 실제 토큰 값과 컴포넌트 props는 코드가 원본이며 이 문서는 역할과 사용자 동작을 설명한다. [과거 마이그레이션](archive/design-migration-2026-07-28.md)의 수치·파일 제한은 현재 작업 규칙이 아니다.

## 스타일을 찾는 위치

| 범위 | 구현 | 적용 원칙 |
|---|---|---|
| 공용 의미 토큰·폰트·포커스 | [index.css](../src/index.css) | `background`, `foreground`, `card`, `primary`, `border`, `ring` 등 역할 이름 사용 |
| 대시보드 테마·상태색 | [theme-tokens.css](../src/styles/theme-tokens.css) | 공용 의미를 화면 역할로 매핑 |
| 페이지 상세 레이아웃 | [page-evidence-layout.css](../src/styles/page-evidence-layout.css) | 컨테이너 크기와 확대에 맞춰 배치 |
| 재사용 입력·대화상자·차트 | [components/ui](../src/components/ui/) | 기존 variant와 접근성 동작을 확인한 뒤 확장 |
| 대시보드 모달 | [dashboard-modals.css](../src/styles/dashboard-modals.css) | 표면·제목·입력·버튼·알림 역할을 공유하며 문서 루트의 테마 토큰으로 portal에도 동일하게 적용 |
| 랜딩 | `.uni-landing`과 `--ua-*` 토큰 | 대시보드 전역 스타일과 범위 분리 |

색상 hex, variant 목록, 모든 breakpoint를 문서에 복사하지 않는다. 동일한 역할의 값을 화면마다 새로 만들지 않고, 반복되는 예외만 공용 토큰이나 variant로 올린다.

## 읽기와 배치

기본 서체는 Pretendard 계열이며 일반 컨트롤·본문은 14px를 기준으로 한다. 한국어 줄바꿈과 긴 URL을 고려하고 수치 비교에는 `tabular-nums`를 사용한다.

대시보드는 조밀한 작업 화면이다. 새 UI는 주요 간격 12–16px, 주요 조작 대상 44×44px, 컨트롤 반경 8px를 출발점으로 삼는다. 실제 컨테이너와 정보량에 맞춰 조정한다. 기존의 작은 트리 아이콘이나 화면별 큰 카드 반경을 새 공용 기준으로 복사하지 않는다.

색만으로 심각도·선택·성공·실패를 표시하지 않는다. 레이블, 수치, 아이콘 또는 패턴을 함께 제공한다. 차트의 중요한 값은 hover 툴팁 없이도 읽을 수 있어야 한다.

## 테마와 모션

light·dark·system에서 같은 정보를 제공한다. 문서 루트의 `.dark`와 대시보드의 `theme-light/theme-dark` 적용을 함께 확인한다. 저장소를 쓸 수 없어도 현재 세션에서 테마가 동작해야 한다.

대시보드의 추가·수정·제거·설정·위치 정보와 로딩·오류 모달은 공통 모달 클래스를 사용한다. 일반 작업 버튼은 파란색, 취소·닫기는 중립색, 실제 삭제 동작은 위험 색상을 사용한다. 버튼은 각 화면의 기존 작은 크기를 유지하며 색상 통일을 위해 일괄 확대하지 않는다. 내용에 필요한 폭과 스크롤 구조는 각 모달에서 유지한다.

모션은 상태 변화를 이해하는 데 필요한 만큼 사용한다. `prefers-reduced-motion`에서는 반복·이동 효과 없이도 상태를 알 수 있게 한다. 투명도 축소와 forced colors에서는 표면·경계·포커스를 구분할 수 있어야 한다.

빠른 분석의 대기 화면은 페이지 도식과 세로 단계 안내를 나란히 배치한다. 좁은 컨테이너에서는 읽을 수 있는 진행 안내를 먼저 두고 도식을 아래에 배치한다. 스캔선은 실제 검사 중에만 움직이며, 완료·오류·상태 확인 대기에서는 멈춘다. 도식은 장식으로 처리하고 현재 단계는 텍스트와 status 알림으로 전달한다. 진행률이나 남은 시간을 임의로 생성하지 않는다.

## 접근성 동작

- 키보드 조작 순서와 읽기 순서는 화면 폭이 바뀌어도 의미가 같아야 한다.
- 본문 바로가기, 현재 위치의 `aria-current`, 아이콘 버튼의 접근성 이름을 유지한다.
- 포커스를 보이게 하고 오류 입력에는 `aria-invalid`와 읽을 수 있는 오류 설명을 연결한다.
- 로딩·비파괴 갱신은 status/live region, 즉시 알려야 하는 오류는 해당 오류 의미로 전달한다.
- 대화상자는 제목, 열릴 때 포커스 이동, Tab 순환, 허용된 Escape 닫기, 닫힌 뒤 포커스 복원을 제공한다.
- 실제 0, 자료 없음, 확인 중, 실패를 구분한다. 연결된 리포트와 위치 확인 완료를 같은 상태로 처리하지 않는다.

프로젝트의 UI 검증 목표는 일반 텍스트 대비 4.5:1, 큰 텍스트 3:1, 주요 UI·포커스 3:1이다. 화면 변경 범위에 맞게 모바일·데스크톱, 200% 확대, 긴 한국어·URL을 확인한다. 표준 적합성 전체를 이 수치 검사만으로 단정하지 않는다.

## 기존 컴포넌트의 제한

- Sidebar는 현재 영구 rail을 사용한다. deprecated `MobileSidebar`를 새 경로의 기준으로 삼지 않는다.
- Stepper는 `asChild` 및 panel 연결에 제한이 있어 컴포넌트 사용만으로 완전한 tabs 동작이 보장되지 않는다.
- 기본 차트 툴팁의 0값 표시와 분석 추이의 빈 슬롯은 별도로 확인해야 한다. 추이 오류는 [아키텍처의 현재 오류](architecture.md)에 기록되어 있다.
- 일부 상태 패널에는 전용 색상이 남아 있다. 정리할 때 의미·포커스·알림 동작을 함께 보존한다.

이 제한을 문서에서 제거하는 것으로 해결된 것으로 처리하지 않는다.

## 변경 확인

기존 토큰·컴포넌트를 먼저 확인하고 변경 범위의 hover, focus, disabled, loading, empty, error를 검증한다. 공용 동작 변경은 호출부와 함께 수정한다.

실행할 검사는 [테스트 가이드](testing.md)에서 고른다. 전역 UI·대화상자 변경에는 접근성 회귀, 랜딩 변경에는 해당 시각 검증, 데이터와 차트 계산 변경에는 단위·화면 검증을 추가한다. 작은 시각 변경에 관계없는 전체 검증을 반복하지 않는다.
